# ChatFiles 本地更新 · 只补新增、不重复分析

> 历史迁移材料：不得作为现行架构或接口规范。请先阅读 [`replication/docs/spec/01_architecture.md`](../../replication/docs/spec/01_architecture.md)。

> [!WARNING]
> **2026-07 起请先执行 [`06_现行安全管线.md`](06_现行安全管线.md)。** 本目录 00-05 保留的是早期原理与历史参考，其中 `crackv4` 覆盖式解密、`data/wechat.db`、按旧 owner ID 计算 delta、直接覆盖洞察文件等命令已经过时，禁止原样执行。

> 这套 **SOP Spec** 面向**已经部署好、装满数据**的本地 ChatFiles（即已跑完 [`../本地部署教程/`](../本地部署教程/)）。它指导 AI **增量**地把以下内容补进项目：
>
> 1. **最新消息**——上次处理之后微信里新增的聊天；
> 2. **之前没解密的消息**——上次没登录、这次登录了的其他微信账号，以及曾被跳过的内容（`.dat` 影像等，可解时）。
>
> 核心承诺：**不重复分析已经分析过的会话**——靠"高水位线（high-water mark）"做增量去重，只对**新增 / 长大**的会话跑提炼，旧 nugget 原样保留、新 nugget 追加合并。
>
> 关键词遵循 **RFC 2119**：MUST / MUST NOT / SHOULD / MAY。

## 什么时候用它

- 隔了一阵，微信里攒了不少新对话，想把它们补进档案馆。
- 上次部署时某个微信账号没登录（解不了），现在登录了，想补上。
- 不想推倒重来（重跑全量提炼又慢又烧额度），只想"增量补差"。

> 如果你是**第一次**部署（空壳还没灌过数据），请先走 [`../本地部署教程/`](../本地部署教程/)，不要用这里。

## 安全红线（与全项目一致，更新时尤其注意）

- **只读原始、只动副本**：重解密仍只写 `work/decrypted/`，原始库 / 文件一字不动。
- **不重复分析 = 不覆盖旧成果**：已分析会话的 `data/insights/conv/*.json` **MUST NOT** 被无脑覆盖；只能在其上**追加 / 合并**新 nugget。
- **高水位单调前进**：`data/insights/_state.json` 记录"每个会话已分析到的文本量 / 时间"，只增不减；据此判断"哪些是新内容"。
- **边界如实**：仍解不了的（QQ 正文、仍未登录的账号）如实记录，**禁止**伪造。
- **个人数据不入仓**：`data/ archive/ work/` 始终 gitignored；身份只在 `.env.local`。
